# Vilki — поиск вилок (surebets)

Сайт ищет **арбитражные ситуации (вилки)** по live- и пре-матч кэфам: парсеры
тянут коэффициенты разных букмекеров, агрегатор сводит их по одному событию,
а движок считает, есть ли вилка и как распределить ставки, чтобы гарантированно
выйти в плюс при любом исходе.

```
парсеры → BookmakerOffer (JSON) → агрегатор (группировка по событию)
        → движок вилок (расчёт) → API (FastAPI) → веб-интерфейс (React)
```

## Что такое вилка

Для рынка из N взаимоисключающих исходов десятичный кэф `o` подразумевает
вероятность `1/o`. Один букмекер всегда закладывает маржу: `sum(1/o_i) > 1`.
Вилка есть, когда, взяв **лучший** кэф по каждому исходу у разных букмекеров,
сумма вероятностей падает ниже 1:

```
arb_index = Σ (1 / лучший_кэф_i) < 1
profit%   = (1 / arb_index − 1) × 100
ставка_i  = банк × (1 / лучший_кэф_i) / arb_index
```

Вся эта математика изолирована в `backend/app/arbitrage.py` и покрыта тестами.

## Структура

```
backend/
  app/
    arbitrage.py        # ★ движок: implied prob, arb index, прибыль, сплит ставок
    models.py           # pydantic-модели: офферы, вилки
    aggregator.py       # сбор офферов, группировка, поиск вилок, запись JSON
    main.py             # FastAPI: /api/surebets, /api/matches, /api/calc, /api/health
    parsers/
      base.py           # интерфейс парсера + нормализация имён/ключей событий
      demo.py           # демо-источник (работает без интернета и ключей)
      the_odds_api.py   # реальные кэфы через The Odds API (по API-ключу)
  tests/                # тесты движка и пайплайна (pytest)
frontend/               # React + Vite: список вилок, фильтры, сплит ставок
```

## Запуск

### Бэкенд

```bash
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload      # http://127.0.0.1:8000
pytest                              # прогнать тесты
```

API сразу работает на **демо-парсере** — открой `http://127.0.0.1:8000/api/surebets`.

### Фронтенд

```bash
cd frontend
npm install
npm run dev                         # http://127.0.0.1:5173
```

Dev-сервер проксирует `/api` на бэкенд (порт 8000).

## Реальные данные

Демо-парсер нужен, чтобы пайплайн и интерфейс работали из коробки. Для живых
кэфов реальных букмекеров (Pinnacle, William Hill, Betfair и др.):

1. Получи бесплатный ключ на <https://the-odds-api.com>.
2. `cp backend/.env.example backend/.env` и впиши `THE_ODDS_API_KEY=...`.
3. Перезапусти бэкенд — парсер `the_odds_api` включится автоматически.

Почему агрегатор, а не один букмекер: вилка по определению требует **нескольких**
букмекеров на одно событие. The Odds API отдаёт сразу набор букмекеров в JSON —
идеальный вход для арбитража. Любой другой источник (включая собственный
скрейпер конкретного БК) подключается как новый класс-наследник `BaseParser` —
движок и API трогать не нужно.

## API

| Метод | Путь | Назначение |
|------|------|-----------|
| GET  | `/api/surebets` | найденные вилки. Параметры: `sport`, `min_profit`, `live_only`, `stake` |
| GET  | `/api/matches`  | все распаршенные офферы |
| POST | `/api/calc`     | посчитать вилку по введённым вручную кэфам |
| GET  | `/api/health`   | статус, число офферов/вилок, состояние парсеров |

Агрегатор также пишет снимки в `backend/data/matches.json` и
`backend/data/surebets.json` на каждом цикле обновления.

## Дисклеймер

Скрейпинг сайтов букмекеров часто нарушает их ToS и технически нестабилен
(антибот, капчи, блокировки по региону). Проект построен вокруг чистого
интерфейса парсеров именно поэтому: легальный источник (The Odds API)
работает сразу, а рискованные скрейперы — на твоё усмотрение. Только для
образовательных целей.
