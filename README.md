# Vilki — поиск вилок (surebets)

Сайт ищет **арбитражные ситуации (вилки)** по live- и пре-матч кэфам: парсеры
тянут коэффициенты разных букмекеров, агрегатор сводит их по одному событию,
а движок считает, есть ли вилка и как распределить ставки, чтобы гарантированно
выйти в плюс при любом исходе.

```
парсеры → BookmakerOffer (JSON) → агрегатор (группировка по событию)
        → движок вилок (расчёт) → API (FastAPI) → веб-интерфейс (React)
```

Рынки: **тоталы (Больше/Меньше) и форы (Ф1/Ф2)**. Источники — парсеры **Olimp**
и **1xbet**. Найденную вилку можно проставить в один клик (по умолчанию —
безопасная симуляция).

## Что такое вилка

Для рынка из N взаимоисключающих исходов десятичный кэф `o` подразумевает
вероятность `1/o`. Один букмекер всегда закладывает маржу: `sum(1/o_i) > 1`.
Вилка есть, когда, взяв **лучший** кэф по каждому исходу у разных букмекеров,
сумма вероятностей падает ниже 1:

```
arb_index = Σ (1 / лучший_кэф_i) < 1
profit%   = (1 / arb_index − 1) × 100
ставка_i  = банк × (1 / лучший_кэф_i) / arb_index
```

Вся эта математика изолирована в `backend/app/arbitrage.py` и покрыта тестами.

**Важно для тоталов/фор:** вилка считается только при **совпадающей линии**
(Тотал Б 2.5 ↔ Тотал М 2.5; Фора1 −1.5 ↔ Фора2 +1.5). Форы нормализуются к
перспективе хозяев, поэтому одна и та же линия совпадает между букмекерами.
Агрегатор группирует исходы по линии и считает каждую линию отдельным
2-исходным рынком.

## Автопроставление ставок

Каркас в `backend/app/betting.py`. По кнопке «Поставить» обе ноги вилки
отправляются через исполнителей (`BetExecutor`) по каждому букмекеру.

- **Paper-режим (по умолчанию):** симуляция исполнения и журнал P&L, без денег.
- **Real-режим (opt-in):** реальная ставка через *твою* авторизованную сессию.
  Нужно задать `OLIMP_SESSION` / `ONEXBET_SESSION` и реализовать
  `<Book>Executor._submit`. Код сам не логинится и не хранит пароли.
- **Риск-контроли:** общий kill-switch, мин. прибыль, макс. ставка, защита от
  повторной ставки на одну вилку.
- **Partial-fill:** если одна нога прошла, а вторая нет — статус `PARTIAL`,
  позиция не захеджирована, это явно подсвечивается (а не проглатывается).

⚠️ Реальные ставки нарушают ToS букмекеров, грозят баном аккаунта и потерей
денег при проскальзывании кэфов. Включай осознанно.

## Структура

```
backend/
  app/
    arbitrage.py        # ★ движок: implied prob, arb index, прибыль, сплит ставок
    models.py           # pydantic-модели: офферы, вилки, ноги ставок
    aggregator.py       # сбор офферов, группировка по линии, поиск вилок
    betting.py          # автопроставление: исполнители, риск-контроли, история
    main.py             # FastAPI: /api/surebets, /api/betting/*, /api/calc, ...
    parsers/
      base.py           # интерфейс парсера + нормализация имён/ключей событий
      olimp.py          # реальные кэфы Olimp (olimpbet.kz) — тоталы + форы
      onexbet.py        # реальные кэфы 1xbet (LiveFeed) — тоталы + форы
      demo.py           # демо-источник (работает без интернета и ключей)
  tests/                # тесты движка, пайплайна, парсеров, ставок (pytest)
frontend/               # React + Vite: список вилок, кнопка ставки, история
```

## Запуск

### Бэкенд

```bash
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload      # http://127.0.0.1:8000
pytest                              # прогнать тесты
```

API сразу работает на **демо-парсере** — открой `http://127.0.0.1:8000/api/surebets`.

### Фронтенд

```bash
cd frontend
npm install
npm run dev                         # http://127.0.0.1:5173
```

Dev-сервер проксирует `/api` на бэкенд (порт 8000).

## Реальные данные

Парсеры **Olimp** и **1xbet** работают из коробки, без ключей.

- **Olimp** (`olimpbet.kz/api/v2/events`) — публичный JSON-API линии, доступен
  напрямую (нужен только заголовок `x-platform`). Проверен вживую.
- **1xbet** (`LiveFeed/GetGameZip`) — публичный API. ⚠️ 1xbet **блокирует IP
  дата-центров** (редирект на `/en/block`); запускай из разрешённого региона
  или укажи рабочее зеркало в `ONEXBET_BASE_URL`. Парсер на блокировке отдаёт
  пусто и не роняет сайт.

Вилка требует **двух** букмекеров на одно событие, поэтому оба парсера
работают вместе. Новый источник подключается как наследник `BaseParser` —
движок и API трогать не нужно. `DEMO_FALLBACK=1` показывает демо-данные, если
оба букмекера недоступны.

## API

| Метод | Путь | Назначение |
|------|------|-----------|
| GET  | `/api/surebets` | найденные вилки. Параметры: `sport`, `min_profit`, `live_only`, `stake` |
| GET  | `/api/matches`  | все распаршенные офферы |
| POST | `/api/calc`     | посчитать вилку по введённым вручную кэфам |
| GET  | `/api/health`   | статус, число офферов/вилок, состояние парсеров |
| GET  | `/api/betting/status` | режим, kill-switch, исполнители, счётчики |
| POST | `/api/betting/toggle` | включить/выключить автоставки `{enabled}` |
| POST | `/api/betting/place`  | проставить вилку `{surebet_id, stake?}` |
| GET  | `/api/betting/bets`   | история ставок |

Снимки пишутся в `backend/data/`: `matches.json`, `surebets.json`, `bets.json`.

## Дисклеймер

Скрейпинг сайтов букмекеров часто нарушает их ToS и технически нестабилен
(антибот, капчи, блокировки по региону). Автопроставление реальных ставок тем
более нарушает ToS и грозит баном аккаунта и потерей денег. Проект — для
образовательных целей; используй на свой риск.
